# Видео-петли

Петли стоят фоном в блоках и в главах Атласа. Их задача — оживить блок, не утащив
за собой мегабайты: основной трафик придёт с телефонов, часто на слабом интернете.

Оригиналы — `Kinsa_media/SORT_VIDEO/`, в репозиторий не идут. В `vid/` попадают
только нарезанные петли. Всего сейчас 12 МБ на 38 файлов.

## Пронумерованные файлы в папке — это одна петля

`ВХОД/ВИДЕО/<где>/<что>/01.mp4, 02.mp4, 03.mp4` — не дубли на выбор, а **планы одной
петли**. Заказчик снимает их подряд именно так: общий вид, потом деталь, потом другая
погода. Собирать надо все, по очереди, по номерам.

⚠️ 21 августа я принял их за дубли, померил движение камеры, выбрал «лучший» и сделал
по одному сюжету на озеро. Пришлось переделывать. Замер движения при этом не пропал
даром — он нужен, чтобы выбрать спокойный отрезок **внутри** каждого файла.

Проверить, как устроена уже готовая петля, можно за секунду:

```bash
ffmpeg -v error -i vid/ИМЯ.mp4 -vf "select='gt(scene,0.25)',metadata=print:file=-" \
  -f null - 2>/dev/null | grep -o 'pts_time:[0-9.]*'
```

У петли Кинсакочи он покажет две смены плана на шести секундах — значит она составная.

**Второй файл почти всегда крупный план воды.** Метрика разницы кадров выдаёт там
огромные числа, но движется не камера, а сама вода — такой кадр в петлю годится
и стоит ровно в середине.

## Главное правило: решает съёмка, а не настройки

Замер одного и того же сюжета, оба раза одинаковые настройки кодека:

| | Вес |
|---|---|
| вода со штатива, 760 px | **191 КБ** |
| вода с проводкой камеры, 1100 px | **2 600 КБ** |

**Разница в тринадцать раз берётся из движения камеры.** Частота кадров и уровень
сжатия дают единицы процентов — пробовали 12/15/20 к/с и crf 30…34, это шум по сравнению
с тем, шевелилась камера или нет.

Отсюда два следствия. Первое: если петля вышла тяжёлой, **не крути crf — бери другой дубль.**
Второе: заказчику сказано снимать фоновые куски с упора, и это стоит повторять.

## Проверить ориентацию до нарезки

Часть исходников снята вертикально — `rotation=-90` в `side_data`. В широкую полосу
они не лягут ни при каком качестве, и это выясняется уже после нарезки, если не посмотреть:

```bash
ffprobe -v error -select_streams v:0 \
  -show_entries stream=width,height:stream_side_data=rotation \
  -of default=nw=1 ИСХОДНИК
```

## Обычная петля

Вариант A, выбран после замеров: **1100 px, 20 кадров/с, 3–4 секунды, crf 30.**
Держится только на статичных дублях — см. выше.

```bash
ffmpeg -ss N -t 3.5 -i ИСХОДНИК -an \
  -vf "fps=20,scale=1100:-2" -c:v libx264 -crf 30 -preset slow \
  -pix_fmt yuv420p -movflags +faststart vid/ИМЯ.mp4
```

## Составная петля: четыре куска в одном файле

Для «Троп хозяина» склеены четыре фрагмента по секунде из разных сюжетов —
огонь, вода Пума Кочи, туман, ичу на ветру:

```bash
ffmpeg -ss N -t 1 -i A -ss N -t 1 -i B -ss N -t 1 -i C -ss N -t 1 -i D \
  -filter_complex "[0:v]fps=18,scale=900:-2,setsar=1[a];[1:v]fps=18,scale=900:-2,setsar=1[b];[2:v]fps=18,scale=900:-2,setsar=1[c];[3:v]fps=18,scale=900:-2,setsar=1[d];[a][b][c][d]concat=n=4:v=1:a=0[out]" \
  -map "[out]" -an -c:v libx264 -crf 33 -preset slow -pix_fmt yuv420p vid/ИМЯ.mp4
```

Четыре секунды — 508 КБ при 900 px и crf 33. Тот же материал при 1100 px и crf 30
весил мегабайт: **смена планов каждую секунду для кодека дорога так же, как проводка камеры.**
Поэтому у составных петель размер меньше, а crf выше — это не небрежность, а расчёт.

## Постер — из самой петли

```bash
ffmpeg -ss 0.3 -i vid/ИМЯ.mp4 -frames:v 1 -q:v 3 /tmp/poster.jpg
cwebp -q 60 -resize 1100 0 /tmp/poster.jpg -o img/ПОСТЕР.webp
```

Берётся именно из готовой петли, а не из исходника: иначе первый кадр окажется чужим,
и в момент запуска будет видно подмену.

## Как петля ставится в разметку

**Видео обязано стоять в разметке с готовым `src`.** Подстановка адреса скриптом
после загрузки в строгих браузерах молча не запускается:

```html
<video src="vid/x.mp4" poster="img/y.webp" autoplay muted loop playsinline
       preload="auto" disablepictureinpicture></video>
```

На главной работает ленивый загрузчик через `data-src` — функция `loadVid`, она проверена,
петли играют. Внутри страниц ставить готовый `src`.

Имя файла — те же первые 12 знаков md5, что и у кадров, либо говорящее (`vid/loop-t1.mp4`).

## Если петля не играет

Мерить **сразу пять величин**, а не одну — по одной картина не складывается:

```js
[...document.querySelectorAll('video')].map(v => ({
  src: v.currentSrc.split('/').pop(), paused: v.paused, ready: v.readyState,
  err: v.error && v.error.code, op: getComputedStyle(v).opacity,
  box: v.getBoundingClientRect().height
}))
```

Через `node .claude/skills/shot/scripts/probe.mjs "..."`. Проверять с флагом
`--autoplay-policy=user-gesture-required`: без него браузер прощает то,
чего не простит телефон.

Частая причина не в видео: **после переписывания блока остался его старый CSS
и мёртвый JS.** Убрали липкую кнопку — обработчик прокрутки остался и ронял скрипт,
а вместе с ним и загрузчик петель.

## Порядок

1. `ffprobe` — ориентация и длительность, выбрать место `-ss`.
2. Нарезать по рецепту выше, посмотреть вес: **больше 700 КБ — брать другой дубль**, не крутить crf.
3. Сделать постер из готовой петли.
4. Поставить в разметку с `src` и `poster`.
5. Проверить скиллом [shot](../shot/SKILL.md) — снимок и пять величин. Не «должно играть».
6. Выкатить скиллом [deploy](../deploy/SKILL.md), не забыв `git add vid img`.

## Чего не делать

- **Не тащить полные файлы на сайт.** Шесть оригиналов — 225 МБ, они убьют скорость.
  Полное видео живёт на Vimeo, в модалке.
- **Не ставить петлю в мелкую ячейку.** В табло на 58 px петля не читалась, их оттуда убрали.
- **Не оставлять звук.** `-an` во всех рецептах не случайно: фоновая петля со звуком
  на телефоне вообще не запустится.
