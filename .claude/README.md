# Скиллы проекта

Скилл — папка с инструкцией, которую Claude подхватывает сам, когда задача под неё
подходит. Живёт в репозитории, значит переживает закрытие чата и работает в любой
новой сессии. Раньше эти скрипты и правила писались заново каждый раз.

| Скилл | Когда включается |
|---|---|
| **shot** | после любой правки вёрстки — снять экран и посмотреть глазами |
| **photo-intake** | заказчик положил кадры в `ВХОД/` |
| **deploy** | правка проверена, пора на живой сайт |
| **oblik** | ★ перед любой правкой вёрстки — палитра, шрифты, линия земли |
| **canvas-design** | нужна отдельная картинка: обложка, плакат, превью для соцсетей |
| **atlas** | добавить вид или кадр в Атлас — правятся данные, не разметка |
| **state** | записать состояние: `STATE.md`, `NEXT.md` и Notion одним заходом |
| **loops** | нарезать фоновую видео-петлю из исходников |
| **skill-creator** | написать новый скилл или проверить, что старые включаются |

Вызвать вручную можно так: `/shot`, `/photo-intake`, `/deploy`, `/oblik`, `/atlas`, `/state`, `/loops`.

Три скилла пришли со стороны и записаны в `skills-lock.json`: `web-design-reviewer`
и `frontend-design` — со Smithery, `canvas-design` — из репозитория `anthropics/skills`.
У `canvas-design` не ставилась папка `canvas-fonts` (4 МБ ttf): облик «Спуск» разрешает
только три своих шрифта из `font/`, чужие всё равно нельзя. Скилл даёт метод, а не шрифты.

## Как устроен скилл

```
.claude/skills/<имя>/
├── SKILL.md        ← имя, описание и сами инструкции
└── scripts/        ← рабочие скрипты, если нужны
```

В начале `SKILL.md` — заголовок с `name` и `description`. Описание решает, когда скилл
включится сам, поэтому пишется как условие: «использовать, когда…».

## Проверка скиллов

`skill-creator` умеет проверять сам себя и соседей:

```bash
python3 -m venv /tmp/skvenv && /tmp/skvenv/bin/pip install -q pyyaml
for s in .claude/skills/*/; do printf '%-22s ' "$(basename $s)"
  /tmp/skvenv/bin/python .claude/skills/skill-creator/scripts/quick_validate.py "$s" | tail -1; done
```

Венв нужен потому, что системный python на этой машине не даёт ставить пакеты (PEP 668).

⚠️ **Двоеточие в описании ломает скилл молча.** `description` — это простая строка YAML,
и `ВХОД: сжать` парсер читает как вложенный ключ. Скилл при этом не регистрируется,
и никакой ошибки не видно. На этом уже попадался `photo-intake`, поправлено 20 августа 2026.
Ставить тире вместо двоеточия или брать всё описание в кавычки.

**Описание — единственный рычаг включения.** Claude чаще не зовёт скилл, когда стоило бы,
поэтому в описании перечисляются живые формулировки: не «использовать после правки»,
а «после правки, а также когда просят показать, проверить на телефоне, снять скриншот».
Описания четырёх старых скиллов расширены по этому правилу 20 августа 2026.

Проверять новые скиллы в ветке `lab`, не в `main`.
